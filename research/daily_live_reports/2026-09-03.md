## Operations And Bugs

1. **Meta's execution gateway calls a property that does not exist on the
   object it is handed.** `core/nervous_system/execution/gateway.py:369` (and
   `:450`, `:640`) do `if not journal_result.is_durable`. `is_durable` is
   defined only on `CompositeJournalResult`
   (`core/nervous_system/execution/journal.py:437-451`); the object actually
   returned is `JournalReceipt` (`journal.py:133`), which has
   `backend/locator/content_hash/status` and no such property. Every Meta
   submission therefore raises `AttributeError` before the broker is called.
   Four pre-open buys and three deferred exits failed at 09:35-09:36 ET.

   change made since then converted a silent false success into a loud failure
   — genuinely better, but Meta has now not traded for two sessions and has 13

## Follow-up (2026-09-04, same session)

Fixes landed for #1, #2 and #3. All are verified by tests that fail against the
pre-fix code and pass after it. **The server has not been restarted, so none of
them are live yet.**

- **#1 Meta gateway.** `JournalReceipt` now reports `is_durable` from its own
  write status (both `WRITTEN` and `IDEMPOTENT` mean the bytes are installed;
  every failure path raises rather than returning a receipt), and the gateway
  routes all five journal writes through a helper that converts a raising sink
  into a not-durable result instead of an escaping traceback.
  `core/nervous_system/execution/{journal,gateway}.py`; three regression tests
  in `test_execution_gateway.py`, one of which reproduces the exact production
  message. The existing `FakeJournal` returns a `CompositeJournalResult`, which
  is why the suite never caught this — the live Meta path passes a bare
  `LocalAtomicJournal`.
- **#2 Stream watchdog.** Thread liveness is now checked at any hour; only the
  staleness rules stay gated on the 09:35-16:05 window. Reviving a dead thread
  backs off 30s -> 600s and resets when bars flow, so a persistent
  `connection limit exceeded` is not hammered. `UI/shared_stream.py`, two tests.
- **#3 SPY loop death.** The urgent market close now catches Alpaca's
  "no available quote ... please reenter with a limit" and falls through to the
  limit ladder, matched on message text so that `insufficient options buying
  power` — same 403, same vendor code — is *not* retried as a limit. The
  expiring-flatten loop no longer lets a failed close escape into `handle_bar`,
  and keeps the position owned rather than forgetting it. The live loop also
  now survives any exception from one bar. `order_policy.py`,
  `UI/live_dashboard.py`, three tests in `test_expiring_flatten.py`.

**#4 (loop saturation) is diagnosed but deliberately not fixed.** Root cause:
every 10-minute decision rebuilds tree features over the entire 553,094-row
1-minute history — measured at **392s** for a 56,706 x 2,299 frame — because
`_build_setup_feature_frame` is handed the full `df_1m`, and because
`_build_base_frame`'s incremental branch is unreachable when the warmup parquet
is missing, as it was. A caching prototype was built and then **rejected**: it
changes 53 of the 430 features the live swing models select (29 go NaN for want
of daily-timeframe history, 24 drift, six of them unbounded accumulators such as
`OBV__30m`, `AD__4h` and `atr_swing_bars_since_flip` that no finite window can
reproduce). Shipping it would have silently altered live model inputs. Full
measurements, the blocking evidence and three routes forward are in
`research/execution_quality/18_spy_loop_saturation_root_cause.md`.
