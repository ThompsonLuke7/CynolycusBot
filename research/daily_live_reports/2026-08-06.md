## Operations And Bugs

1. **Option stops blow through the -39% threshold, badly.** Nine option stops
   today and on 08-07 realized a mean of -57.1% against a -39% label; WDC
   realized -88.5%. Mechanism: `core/live_4h_exec.py:62` sets
   `stop_loss = 0.39` and it is evaluated once per 4H bar. The code comment on
   that same line says the parameter came from a **shares-only backtest** with
   "no option-premium path modeled, so real option stop/trail behavior may
   differ; not yet paper-validated live." That caveat is now measured: on a 4H
   check grid, an option carrying 3-8x the underlying's effective leverage
   routinely gaps past -39% between checks. The threshold is not being enforced;
   it is only being observed after the fact. Highest-value fix available.
2. **Settled close vs snapshot marks disagree by ~$13,851.** The 20:05 snapshot
   recorded equity $866,109.88, but Alpaca's official prior close read from the
   08-07 snapshot is $879,960.75. Both snapshots are taken during extended hours
   and carry extended-hours marks on a book that is 29 option positions deep.
   The settled figure is the one to trust for daily attribution; the report leads
   with it. Worth deciding which the scorecard should use going forward.
3. **Restored-position `pnl_pct` still logs 0.0.** Carried over from the 08-05
   report and still unfixed — visible again on 08-07 (UMC, TKR). Not triggered
   today but the code path is unchanged.
4. **Two unverified swing buys** (`T`, `PNC`, both `status=new via=timeout`).
   Correctly skipped from local position opens. Not a defect; noting that the
   guard fired.
5. **One parquet save_back failure** (`TECH`, ENOENT) in the swing feature
   builder. Single occurrence, non-fatal.
6. **Two QQQ dealer poll failures** (Schwab chain lookup). Transient, recovered.
7. **Data readiness stamp was stale at startup** and forced a 45-minute catch-up
   (08:32 -> 09:17, exit 0). It finished before the 10:00 ET bar so no entries
   were blocked, but the scheduled 22:15 ET readiness never fires because the
   server is stopped before then each evening. This is a standing structural
   risk: a slower catch-up would block the first 4H bar outright.

Server health was otherwise clean — `watchdog_20260806.log` contains only the
startup line, no restarts, no exit 137, no missed heartbeats.
