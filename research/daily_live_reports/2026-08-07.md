## Operations And Bugs

1. **Dealer Ranker: a transient DNS outage was silently recorded as "nothing is
   optionable."** Between 15:47:39 and 15:50:56 ET the host lost name
   resolution (21 `Temporary failure in name resolution` warnings across
   live_dashboard, swing reconcile, and dealer polls; the Alpaca bar websocket
   dropped and reconnected three times, and `SharedBarStream` reported bars
   stale for 199s). The Dealer Ranker's optionable scan ran inside that window.
   In `strategies/dealer_positioning/live_ranked_options.py:465`,
   `_select_atm_option` wraps its contract fetch in
   `except Exception: return None, f"contracts_error({exc})"`, and the caller at
   line 402-425 treats *any* `None` as "skip this ticker as not optionable."
   DNS failures return instantly, so all 100 scanned names failed in about one
   second, the scan hit its cap, and the module wrote an audit row that is
   indistinguishable from a legitimately illiquid universe. Evidence: the audit
   was written at 15:48:27, one second after `dealer rankings refreshed`, and
   the skip count is exactly the scan cap. Contrast 08-06, which skipped 66 and
   kept 10.
   This directly violates the repo rule to fail fast rather than continue with
   invalid data. Suggested fix: distinguish `contracts_error(...)` from the
   liquidity-rejection reasons already being returned, and abort the run (or
   retry) when the error share crosses a threshold, rather than emitting an
   empty target list. A scan that reaches its cap with zero keeps should never
   be reported as a normal outcome.
2. **Option stops blow through the -39% threshold.** `core/live_4h_exec.py:62`
   sets `stop_loss = 0.39`, evaluated once per 4H bar. Across 08-06 and 08-07,
   nine option stops realized a mean of -57.1% (worst -88.5%, WDC on 08-06);
   even a 1-bar hold overshot by 12.9-18.7pp. The comment on that same line
   records that the parameter came from a shares-only backtest with "no
   option-premium path modeled ... not yet paper-validated live." It is now
   validated, and it fails: on a 4H grid an option carrying several times the
   underlying's leverage gaps past the threshold between checks. The threshold
   is observed, not enforced. This is the highest-value fix available and it
   compounds with #4.
3. **Restored-position `pnl_pct` logs 0.0** while the option leg is at -45%
   (UMC, TKR). Third report in a row carrying this; still unfixed. It makes the
   swing audit's own P&L column untrustworthy for restored positions.
4. **The option overlay is the entire loss.** 29 option positions carry -$16,537
   against 170 equity positions at +$9,433. Same pattern on the closed side:
   the only winners across both days were equity take-profits and two option
   trails, while every option stop was a large loss. Worth an explicit decision
   on whether the option route earns its leverage at the current stop cadence.
5. **Cash is negative (-$49,031)** with 199 positions and $918k of market value
   on $869k of equity. Nothing has breached a broker limit, but the book is
   levered and position count has grown on each of three consecutive losing
   days. There is no evidence of a de-risking or position-count cap responding
   to the drawdown.
6. **Data readiness stamp was stale at startup** and forced a 45-minute catch-up
   (07:29 -> 08:14, exit 0). It finished before the 10:00 ET bar so no entries
   were blocked. Recurring: the scheduled 22:15 ET readiness never fires because
   the server is stopped each evening before then. A slower catch-up would block
   the first 4H bar outright.
7. **Minor/transient:** four unverified swing buys correctly skipped from local
   opens (XLRE, KKR, CW, CVNA, all `status=new`); one Alpaca 429 on a FANG
   option quote; three websocket communication errors during the outage, all
   recovered by 15:50:56.

Server health: `watchdog_20260807.log` contains only the startup line — no
restarts, no exit 137, no missed heartbeats. Process 1801 has been up since
07:47 ET. Memory keeper reported RSS ~1,898 MB mid-session, well below the
levels that preceded past OOM events.
