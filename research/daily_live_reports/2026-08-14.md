## Operations And Bugs

**1. Expiry-day exit ladder treats "accepted" as "filled", loses $9,594 and
records it as `pnl=None`.** (Critical.)

Sequence at 15:53 ET, from `server_20260812.log`:

```
15:53:04,863 WARNING exit ladder: market sell rejected for HPE260814C00060000
             (403 "no available quote for symbol. please reenter with a limit") — repricing as limit
15:53:05,190 INFO    exit ladder: HPE260814C00060000 accepted at limit 0.01 (1/1)
15:53:09,697 INFO    realized-PnL logged: dealer_ranker HPE260814C00060000 qty=52 reason=stop_-50% pnl=None
```

Identical sequence for ZM at 15:53:10-15:53:15. Three compounding failures:

- The ladder repriced a market order into a **$0.01 limit sell** on a contract
  with no bid. That order could never fill.
- Acceptance was treated as completion: the module logged a realized exit and
  dropped the position from `managed` four seconds later, without verifying a
  fill.
- The realized P&L was written as `None`. The actual -$4,784 (HPE) and -$4,810
  (ZM) never entered the realized ledger, so every downstream P&L rollup is
  understated by $9,594.

The orphaned positions were then adopted by the swing 30m module at 19:53:27 UTC
as `restored_from_broker`, which tried its own defensive exit and got:

```
19:55:05 ERROR [ZM] sell order FAILED: 403 "account not eligible to trade uncovered option contracts"
20:00:55 ERROR [ZM] sell order FAILED: 422 "contract ZM260814C00110000 is expired"
```

The 403 is itself a signal — the broker did not think the account held enough of
that contract to cover the sell, consistent with the local/broker quantity drift
documented above. Both contracts expired worthless.

This is a stuck-position class that needs a human decision, not a retry: the
ownership boundary between Dealer Ranker and swing 30m is undefined for
broker-restored positions, and both modules acted on the same contract.
