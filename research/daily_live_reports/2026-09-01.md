## Operations And Bugs

1. **Cross-module option-position collision, and a rejected-order hot loop
   (critical, still active at report time).** The chain, all times ET:

   | Contract | Intraday Structure BUY | Swing 30m adopted it | Swing 30m liquidated it |
   |---|---|---|---|
   | QQQ260901P00708000 | 10:27:05 | 10:27:36 | 10:30:08 |
   | IWM260901P00293000 | 10:32:03 | 10:32:59 | 10:35:06 |
   | WMT260904P00106000 | 11:12:45 | 11:12:56 | (Intraday sold it 11:29:50) |
   | QQQ260901C00717000 | 11:56:48 | 11:57:44 | 12:00:14 |
   | IWM260901C00294000 | 12:10:45 | 12:10:47 | 12:15:03 |

   Swing 30m's broker reconciliation treats any option position it does not
   recognize as a "restored unknown" position, adopts it, and — for same-day
   expiries — force-exits it about 2.5 minutes later under
   `restored_unknown_expiring`. Intraday Structure holds no cross-module claim
   and is never told. It then tries to sell contracts the account no longer
   holds, which Alpaca reads as *opening* a naked short and rejects.

   The rejections escalate through three messages as conditions change:
   - 403 `account not eligible to trade uncovered option contracts` (3,272 today)
   - 422 `contract "..." expires soon, unable to open new positions` (3,271)
   - 422 `options market orders are only allowed during market hours` (3,343,
     from 16:15 ET onward once the after-hours rule started binding first)

   `IntradayOptionExecutor._close_position`
   (`strategies/intraday_structure/execution.py:313-332`) deliberately keeps the
   position in `self._open` on failure so a later event retries. But
   `maybe_flatten_expiring` is driven by the runner's clock, not by events, and
   `strategies/intraday_structure/runner.py:270` and `:273` call it on **both**
   the bar path and the 1-second `queue.Empty` timeout path. So a permanently
   failing exit becomes a retry loop with no backoff and no circuit breaker.
   First rejection 10:45:44 ET, last 00:00:00 ET: **96,793 rejected submissions**
   at roughly 190 per minute, and 26 MB of server log.

   It stopped at midnight, but not because anything recovered.
   `_maybe_flatten_expiring` returns early when the local time is before
   `expiring_exit_hhmm` (15:40), and that gate is time-of-day only — so the loop
   is dormant 00:00-15:40 and resumes at 15:40 every day for anything still
   claimed. An expiry already in the past still satisfies `exp <= today`
   forever, so a restart alone would not have cleared it either.

   Four of the five stuck claims left the state file at 00:07:04 ET with no SELL
   log, no ledger row, no exception and no server restart. That mechanism is
   unattributed. The outcome was verified read-only against the broker at
   00:10 ET: only V260904C00380000 is still claimed, and the account does hold
   it (5 contracts, matching).

   Three separate defects here, all fixable independently:
   - **Ownership.** Swing 30m should not adopt option positions belonging to
     another module. There is no shared claim registry; `live_risk_pass`'s orphan
     detector sees the same positions and only warns.
   - **Fill verification.** `_on_entry`
     (`strategies/intraday_structure/execution.py:187-218`) records the position
     from the *submit* response and never re-polls. Every stuck row still shows
     `entry_filled_qty: 0.0` and `entry_fill_price: null` even though the buys
     did fill — so the module's own state cannot tell a filled position from an
     unfilled one, or a liquidated one from a held one.
   - **Retry discipline.** No backoff, no attempt cap, no session gate.
     `_close_position` hardcodes `order_type="market"` with no market-hours
     check, unlike the 4H modules which route through
     `core.live_4h_exec.defer_exits_if_opg_unavailable`.

2. **Watchdog logged a silent server disappearance.** `watchdog_20260828.log`

4. **Momentum Expansion is out of options buying power.** Seven option entries

## Fixes Applied (2026-09-02, same session)

Committed to the working tree; **a server restart is required for any of it to
take effect** — the running process still holds the old code.

1. **One ownership reader.** `core.orphan_positions.claimed_symbols()` now unions
   every module's book — the four 4H `managed` states, multi_ticker_swing's
   position list, the SPY daytrader's, and intraday_structure's
   `open_option_positions.json`, which was in none of them. It takes an
   `exclude=` argument so a module can ask "what do my *siblings* claim".
   `find_orphans` uses it. intraday_structure claims the OCC contract only,
   never the bare underlying, because its names are index ETFs every other
   module also trades.
2. **Swing 30m reads that instead of its own list.**
   `_sibling_module_owned_symbols` in `position_manager.py` no longer keeps a
   private `_SIBLING_MODULE_STATE_PATHS` tuple — the list that drifted. Its
   existing `owned_by_other_module` veto is unchanged; it now simply sees
   intraday_structure.
3. **Fill verification.** `_on_entry` polls the order rather than reading
   `filled_avg_price` off the submit response, records the real fill price and
   filled quantity, sizes the claim to what actually filled (not what was
   requested), and cancels-and-does-not-claim an entry that never fills.
4. **Broker truth before every exit.** `_close_position` checks the account
   actually holds the contract, releases the claim if not, and corrects the
   quantity if it differs. A broker outage returns None and never drops a claim
   — "unreachable" and "you hold nothing" are kept distinct.
5. **Shared exit policy.** Exits route through
   `core.live_4h_exec.submit_option_exit_with_ladder` (market rung, then a
   descending limit ladder) instead of a bare market order, so an after-hours
   exit is priced rather than rejected. Fill price comes back via
   `poll_exit_fill_price`, which is what makes `realized_pnl` recordable at all.
6. **Retry discipline.** Per-position attempt counter with exponential backoff
   (30s doubling to a 900s cap) and a hard cap of 8 attempts, after which the
   position is quarantined and generates no further orders. Worst case is now
   ~8 attempts over ~45 minutes instead of 96,793 over 13 hours.
7. **Startup reconcile.** `_restore()` checks the restored book against the
   broker and releases claims the account cannot confirm, so a restart clears a
   stuck book instead of resuming the loop.
