## Operations And Bugs

1. **WSL2 crash killed the readiness job (root cause of the dead trading day).**
   The previous server instance stopped writing at 06:07 ET with no shutdown
   message; the box rebooted at 08:17 ET and the server restarted at 08:18 ET.
   The 05:30 ET `nightly_data_readiness` job had launched but never completed, so
   `Data/readiness/latest_success.json` still reads
   `completed_at_utc: 2026-07-23T10:13:05`. Because the server came up after the
   05:30 slot, the job never re-ran. This matches the previously logged pattern of
   manually-started `combined_server` dying on recurring WSL2 crashes.
2. **Readiness gate blocked 100% of 4H entries.** `core/live_readiness.py`
   requires a stamp newer than the prior session's 16:00 ET close. Nine planned
   entries (Meta 3, Momentum 5, HTF 1) plus three queued pre-open entries were
   dropped. The gate behaved exactly as designed — the failure is that nothing
   re-runs the readiness job or alerts when the stamp goes stale. There is no
   catch-up path and no notification; the modules simply went quiet all day.
   **This will repeat on Monday unless the stamp is refreshed**, and the server is
   currently stopped, so the Monday 05:30 ET slot will also be missed if it is not
   restarted first.
3. **Option routing has never selected an option.** In
   `signals/meta_context/meta_ranker/options_exec.py` the selected-contract
   snapshot is read with `sel_snap.get("openInterest")` and
   `sel_snap.get("dailyVolume")` — camelCase keys that the Alpaca
   `get_option_snapshots` payload does not provide — so both coerce to 0 and the
   `ROUTE_MIN_OPEN_INTEREST=500` / `ROUTE_MIN_VOLUME=100` floors always fail.
   Evidence: across the full recorded audit history the routing action tally is
   294 `equity` and 0 `option`, and all 181 illiquid rejects are the identical
   string `illiquid_option(oi=0,vol=0)` — never a partial value such as
   `oi=300,vol=50`, which is the signature of missing fields rather than genuinely
   thin markets. Rejected names include APLD, RNG, SEDG, and DOCN, all of which
   have liquid listed options. Commit 088e833 propagated the same field names into
   `strategies/dealer_positioning/live_ranked_options.py`, which is why the Dealer
   Ranker skipped all three of its targets today.
4. **Momentum state file over-reports order counts.** `runner.py:499-501` appends
   `{"orders": len(res.plan)}` using the pre-filter plan, while `execute_plan`
   applies the readiness filter internally. Today's history therefore records
   `orders: 2` and `orders: 3` for a session in which zero orders were submitted.
   Meta and HTF do not have this defect (no history row was written for today).
   Managed state itself is clean — none of the blocked tickers leaked in.
5. **Dealer IOT stop-loss exit failed and the contract has now expired.** The
   market-order exit was rejected HTTP 403 for lack of a quote on a 0DTE contract.
   The correct fix is a limit order on the exit path for expiring contracts; the
   position needs a human look rather than a retry.
6. **Swing audit does not persist exit fills.** Every `order_submitted` response
   is captured at `status: pending_new` with `filled_avg_price: null`, and for the
   two `restored_unknown_expiring` closes `option_last_price` was never refreshed
   off the entry price. That makes audit-derived swing P&L unreliable — the VZ
   close reads as $0 in the audit against roughly -$2,772 in reality. Note also
   that `exit_pnl_pct` in the swing audit is the **underlying** return, not the
   option return (VZ shows +2.69% underlying while the option lost ~54%).
7. **Broker snapshot `unrealized_intraday_pl` is wrong for same-day opens.** In
   the 20:05 ET snapshot, PRIM/DIA/HON show intraday values of -$2,240/-$3,010/
   -$1,560 against true `unrealized_pl` of -$1,280/$0/+$520. Use the 16:05 ET
   snapshot for intraday attribution. Option marks were also identical between the
   16:05 and 20:05 snapshots, i.e. not refreshed after the close.
8. **NaN-served feature:** the swing ranker scanner reported 1/192 features absent
   from the live builder — `gap_fill_rate_60d`.
9. **Theme explorer publication failed:** `theme explorer publication exit=1`,
   *"Git staging failed with exit code 128"*. The build itself succeeded
   (155 themes, 232 links, 3,202 tickers); only the publish step failed. The
   working tree still shows `themes/dynamic_theme/viz/theme_explorer.html` as
   modified.
10. **Server is currently stopped.** Clean shutdown at 23:47 ET via the supervisor
    — not a crash — but nothing is running now.
